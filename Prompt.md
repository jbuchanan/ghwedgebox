## Prompt

Create editable, coordinated design variations of the three supplied Wells Fargo app screens.
OBJECTIVE
An executive has requested a cleaner, more modern, and more consistent interface. Treat the three screens as one product experience, preserving each screen’s content, functionality, and purpose.
SOURCE
- Preserve the originals and create new frames for explorations.
- Use the original screen dimensions.
- If the sources are screenshots, reconstruct the UI as editable elements.
- If reference text is unreadable, flag it rather than inventing it.
- Use the connected design library where available, including components, text styles, colors, and spacing variables.
- Where the library does not support a proposed treatment, identify the gap and use clearly labeled local exploration components.
CREATE SIX DIRECTIONS
1. Comfortable cards: shared card styling with generous spacing.
2. Compact cards: the same card system with tighter spacing.
3. Comfortable sections: clear headings, whitespace, and subtle dividers.
4. Compact sections: the same section system with tighter spacing.
5. Comfortable mixed layout: cards for primary information and simple rows for secondary content.
6. Compact mixed layout: the same mixed system with tighter spacing.
Every direction must include ALL THREE screens.
CLEAN, MODERN VISUAL LANGUAGE
Apply these principles across all six directions:
- Calm, uncluttered layouts with clear visual hierarchy.
- Crisp, readable typography with consistent sizes and weights.
- Deliberate whitespace, aligned edges, and consistent spacing.
- Subtle borders, restrained corner radii, and minimal shadows.
- Quiet backgrounds and secondary surfaces.
- Purposeful use of the existing Wells Fargo brand colors.
- Consistent icon styling, sizing, and alignment.
- Clearly recognizable primary actions and subordinate secondary actions.
- Reduced decorative clutter while preserving content and navigation cues.
- Avoid decorative gradients, glass effects, oversized rounding, and excessive floating cards.
Comfortable versions should feel spacious. Compact versions should feel efficient while maintaining readable text and usable touch targets.
CONSISTENCY AND CONSTRAINTS
- Apply shared rules within each direction for headers, navigation, typography, spacing, cards, rows, icons, buttons, and action hierarchy.
- Present equivalent information and actions consistently.
- Preserve differences justified by each screen’s task.
- Preserve all content, values, labels, disclosures, functionality, and navigation destinations.
- Do not invent features, financial information, marketing copy, or controls.
- Keep grouping and density as the main differences between directions.
- Preserve brand identity and follow the connected library’s requirements.
BUILD AND PRESENTATION
- Use editable text, auto layout, reusable components, and existing styles and variables wherever appropriate.
- Keep existing component instances connected to their main components where possible.
- Do not modify shared library main components.
- Arrange directions in rows and corresponding screens in columns.
- Label each row with its direction number, name, and a short explanation of its rules and tradeoff.
- Keep annotations outside the app screens.
CHECK
Check for altered or omitted content, clipping, overlap, unreadable text, and inconsistent repeated elements. Correct issues and identify any unresolved limitations.
EXECUTION
Start with Directions 1 and 2 only: three screens per direction, six editable frames total.
When I say “next,” create Directions 3 and 4.
When I say “next” again, create Directions 5 and 6.
Always work from the original sources and these constraints. Preserve all previously completed directions.
